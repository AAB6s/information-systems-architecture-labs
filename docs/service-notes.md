# TP04 — Service Notes

## A. Injection Modes

| Mode | Final field | Dependency visible | Usable outside Spring | SonarQube for IDE |
| --- | --- | --- | --- | --- |
| Constructor | Yes | In the constructor | Yes, with a repository supplied | Preferred |
| Field | No | Hidden inside the class | The field stays null | S6813 flags field injection |

All AutoLoc services use one constructor generated by Lombok `@RequiredArgsConstructor`. Spring supplies the repository proxy; `@Autowired` is unnecessary.

## B. Services

| Service | Injected dependency | Injection | Reason |
| --- | --- | --- | --- |
| AgenceServiceImpl | IAgenceRepository | Constructor | Agency persistence |
| EmployeServiceImpl | IEmployeRepository | Constructor | Employee persistence |
| VehiculeServiceImpl | IVehiculeRepository | Constructor | Vehicle persistence |
| EquipementServiceImpl | IEquipementRepository | Constructor | Equipment persistence |
| ClientServiceImpl | IClientRepository | Constructor | Client persistence |
| ReservationServiceImpl | IReservationRepository | Constructor | Reservation persistence |
| ContratServiceImpl | IContratRepository | Constructor | Contract persistence |
| PaiementServiceImpl | IPaiementRepository | Constructor | Read-only payment lookup |
| MaintenanceServiceImpl | IMaintenanceRepository | Constructor | Maintenance persistence |

`@Service` makes each implementation a Spring bean. Each service is stateless and depends on a repository interface. Creation rejects an existing identifier. Updates load the stored row and copy scalar fields without replacing its identifier or collections. Missing records raise `ResourceNotFoundException`. `Contrat.paiements` uses `CascadeType.REMOVE`, so deleting a contract deletes its payments.

The nine controllers in `web.controller` are annotated with `@RestController` and `@RequiredArgsConstructor`. Each injects its `I…Service` interface into a final field; no controller accesses a repository directly. Routes are `/api/agences`, `/api/clients`, `/api/contrats`, `/api/employes`, `/api/equipements`, `/api/maintenances`, `/api/reservations`, `/api/vehicules` and `/api/paiements`. The first eight expose create, find, list, update and delete; payments expose read operations only. Creation returns 201 with Location, deletion 204, missing resources 404 and invalid business inputs 400. `@JsonIgnore` on inverse associations prevents recursive JSON output without changing the JPA mapping.

## C. Container Errors

1. A missing `IContratService` bean can mean `@Service` is missing from `ContratServiceImpl` or the class is outside the `tn.esprit.autoloc` scan. Restore the annotation or move the class into the scanned package.
2. Two notification beans cause `NoUniqueBeanDefinitionException`. Put `@Primary` on the intended default implementation, or put `@Qualifier` on the consuming constructor parameter to choose one explicitly.
3. A cycle between client and reservation services causes `BeanCurrentlyInCreationException`. Constructor injection exposes the cycle because neither object can be constructed first. Move shared logic to a separate dependency and remove the mutual injection.

## E. Understanding

1. There is no `new ContratServiceImpl` in the project. Spring calls its constructor when it creates the service bean.
2. A controller depends on `IContratService` so the service implementation can change without changing the controller.
3. A singleton is shared between requests. Keeping a mutable `currentContract` field could mix two users' requests.
4. `update` loads the stored entity before copying changes so a partial input cannot overwrite unrelated fields or payment links.
5. `@Component` marks a class for scanning; `@Bean` declares an object through a configuration method. `@Primary` chooses a default bean of a type; `@Qualifier` chooses a named bean at an injection point. `IPaiementService` has no write methods because payment changes pass through the contract.
